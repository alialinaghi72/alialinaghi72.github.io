## 1. Conventions

### 1.1 Severity semantics
Severity states **what the defect does to a resource estimate**, not how hard it is to fix.

| Severity | Meaning for estimation use | Typical examples | Engine and scoring effect (01 §7.6, §8) |
|---|---|---|---|
| **CRITICAL** | The record, table or whole dataset **cannot be used as is**. At least one export target would merge, drop or misplace the data, or the dataset as a whole cannot support public reporting. | Duplicate HoleID; X/Y swapped or wrong UTM zone; no QA/QC at all; a CRM written into a drillhole interval; required field absent | Weight 20. Caps the hole score at 40. A project-level CRITICAL caps the DCI at 40. **Release gate:** must be fixed, or ignored with a reason by a named reviewer, and is then printed in the executive summary. |
| **ERROR** | A definite defect that changes the **position, length, grade or identity** of data. If uncorrected, it changes the model. | From ≥ To; overlap; survey beyond EOH; CRM failure; orphan assay; value differs from certificate | Weight 5 (≈ ×0.61 on the component per error at τ = 10). `QC_FLAG = E` on export. Must be resolved before the data are described as supporting Indicated. |
| **WARNING** | The data are usable but their **accuracy or geological meaning is doubtful**. Review is needed; the finding may be legitimate (a twin, a genuine high grade, a real dogleg). | Handheld-GPS collar; azimuth spike; thin interval; logged sulphide inconsistent with S | Weight 1 (≈ ×0.90). `QC_FLAG = W`. |
| **INFO** | Inventory, context or a statistic the estimator should know. **No penalty.** | Collar without interval data; non-standard sample length; normalisation counts; spacing statistics | Weight 0. Feeds the narrative and the JORC evidence scorecards (01 §8.3). |

**Decision test used throughout this catalogue.** If an estimator saw this finding:
- and could not build or trust the dataset at all → **CRITICAL**;
- and would certainly change the model if it is left uncorrected → **ERROR**;
- and might change the model, depending on review → **WARNING**;
- and would not change the model but must know it → **INFO**.

**Interaction with export targets** (research note RB on the severity model). CRITICAL and ERROR mean that at least one target package will exclude, average or misplace the record. Datamine averages overlapping and duplicate records; Leapfrog drops rows in its error tables. WARNING means the record is processed, but its meaning is doubtful. GEOVALID never copies vendor "quick fixes" such as "keep first record" or "delete hole", which depend on file order or destroy data. It proposes and logs.

### 1.2 Rule ID scheme
- Format `FAM-NNN` (02 §5.5 `CHECK`). Families: IMP, COL, SUR, INT, ASY, QAQ, LIT, GEO, ALT, MIN, WTH, DEN, MAG, STR, SMP, CRS, SPA, VER.
- **Brief §17 IDs keep their numbers and meaning.** In a few cases this catalogue makes a brief rule's logic more precise or extends its scope, e.g. INT-003 also covers point tables. Each such case is stated in the rule's Notes. No brief rule changes meaning.
- New rules continue after the last brief ID of the family (COL-016 onward). Families without brief rules start at 001 (IMP, MIN, MAG, STR, SMP, VER).
- **`FAM-901` to `FAM-999` are reserved for project-defined declarative rules** (01 §5.11): `inequality`, `range`, `required_if`, `pattern`, `forbidden_sequence`. This catalogue confirms the reservation. The brief's "user-defined inequality rules" (§6.2) and "user-defined forbidden sequences" (§7) are implemented there, not as catalogue rules.
- IDs are never reused. A withdrawn rule keeps its ID with status `RETIRED` in the registry, so old issue logs stay readable.

### 1.4 Dual-threshold bands, escalation and demotion
Implemented by 01 §5.6. Notation in the tables:

| Notation | Meaning |
|---|---|
| `bands: W 3 · E 6 °/30m` | The rule computes a **measure**. A measure ≥ 3 gives WARNING, and ≥ 6 gives ERROR. Below the lowest band there is no issue. Bands are profile-editable (`rules.<ID>.bands`). |
| `bands_by: <key>` | **Contextual bands**: thresholds are chosen by a categorical key, e.g. COL-011 by `drv_collar_method.inferred_method`. |
| `↑ERROR if count_per_hole ≥ 3` | **Aggregate escalation** after grouping. Available aggregates: `count_per_hole`, `count_per_table`, `share_of_table`, `count_project`, `share_of_holes`. |
| `↓INFO when …` | **Demotion** by the rule's own logic, with a `demotion_reason` stored in `issue_context`. |

**Base-profile escalations that apply to many rules:**
- (E1) Any ERROR-class INT or SUR rule with `share_of_holes ≥ 0.25` raises one **project-level** issue of the same rule ID at CRITICAL. The message reads "systemic: affects n % of holes". Individual issues keep their severity.
- (E2) A WARNING-class location rule (COL-010, COL-011, COL-013) on ≥ 50 % of collars in a campaign raises one campaign-level ERROR.

Per-rule escalations are given in the Severity column.

### 1.5 Parameters
- Names are **snake_case with the unit in the name**:
  - `_m`, `_deg`, `_deg_30m`, `_pct` (0–100), `_frac` (0–1), `_ppm`, `_gpt`, `_x_dl` (multiple of the detection limit), `_sd` (multiple of a standard deviation), `_days`, `_kg`, `_g`, `_gcm3`, `_e3_si`, `_nt`;
  - `_n` for counts, `alpha` for a significance level;
  - booleans start with `is_`, `require_` or `allow_`; code lists end in `_codes`.
- Example names: `max_gap_m`, `near_dup_distance_m`, `blank_warn_x_dl`.
- Every default is editable, is validated by the rule's `Params` model (01 §5.2) and is printed in the report appendix with its origin: base, deposit or project (§19).
- Shared settings are read from the profile, not duplicated per rule. Examples: `schema.depth_eps_m` = 0.001 m (02 §2.2), `qaqc.sd_warn` / `qaqc.sd_fail` = 2 / 3, `qaqc.dup_min_mean_x_dl` = 10, `assay.bdl_policy`, `desurvey.method`, and the profile `cutoff` per key analyte (§4).

### 1.6 Declared inputs ("Needs")
Each logic cell begins with **⟦…⟧**, listing the derived products (01 §6.2) and optional inputs the rule declares in `RuleMeta.requires`:
- products: `drv_trace`, `drv_trace_compare`, `dem_surface`, `drv_collar_spatial`, `drv_collar_method`, `drv_assay_wide`, `drv_qaqc_crm/_blank/_pair/_batch`, `drv_interval_master`, `drv_composite`, `drv_pierce_point`, `drv_hole_summary`, `kdtree`;
- optional inputs, written `layer:<kind>` (02 §4.21 `spatial_layer.kind`) or `table:<name>`.

If a declared input is missing, the task is `NOT_APPLICABLE` in the rule-execution matrix with the missing item named (01 §5.1). **A missing input is never a pass.** Rules without a ⟦…⟧ tag read only canonical tables.

### 1.7 Proposed fixes
The "Proposed auto-fix" column describes the `propose_fix()` template (01 §5.2). It becomes a **DRAFT change set only on reviewer action** and is **never applied automatically** (§0).
- Op names follow 02 §5.7: `SET`, `VOID`, `INSERT`, `RELINK_HOLE`, `DATUM_SHIFT`, `ALIAS`, `DICTIONARY`.
- `—` means no data fix is meaningful.
- `FIELD:` names an action outside the database (re-survey, re-assay, re-log, request certificate).

### 1.9 Statistical rules: minimum detectable effect (MDE) and gate protocol
Deterministic rules are gated by 100 % recall on injected errors and zero issues on the clean twin (01 §5.12, 04 P11). **Statistical rules** are gated by a power / false-alarm protocol. Each rule is run on 200 clean seeds and on 200 seeds with the effect injected at the MDE, and must achieve:
- **power ≥ 0.90** at the MDE;
- **false alarms on clean seeds ≤ the nominal α** for test-based rules, or **≤ 1 issue per 100 holes** for per-record outlier rules;
- for FDR-controlled rules (SPA-001, SPA-002), an observed false-discovery proportion ≤ q.

Two-sided shift MDE at α = 0.01 and power 0.90: **δ = (z₀.₉₉₅ + z₀.₉₀)·σ/√n = 3.86·σ/√n**. For two independent groups this becomes **d = 3.86·√(2/n)** standardised units with n per group. The formula is quoted per rule below.

| COL-010 | Weights-of-evidence classifier | EC-3.03 metrics (accuracy ≥ 90 %, PLANNED recall ≥ 95 %) on ≥ 2 000 synthetic collars |

### 1.10 Notation used in logic cells
- `ε` = `schema.depth_eps_m`.
- `|a−b|∘` = wrapped angular difference `min(|a−b|, 360−|a−b|)`.
- `I = 90° + dip` = inclination from vertical (02 §4.22).
- `robust z = (x − median)/(1.4826·MAD)`.
- `BH` = Benjamini–Hochberg.
- "Key analytes" are the profile's `commodities` plus the elements listed in its §4 block.
- "Mineralised" means inside a logged interval whose code has `mineralisation_class = MINERALISED`, or a composite above the profile `cutoff`.
- Duplicate-statistic definitions (QAQ family):
  - **HARD** (half absolute relative difference; Shaw 1997, as used by Abzalov 2008): `HARD = 100·|a−b|/(a+b)`. HARD is half of the absolute relative difference `ARD = 200·|a−b|/(a+b)`, which some authors call AMPD.
  - Signed **MPD** (mean paired relative difference): `MPD = mean(200·(a−b)/(a+b))`. It measures bias.
  - Pair CV: `CV_i = √2·|a−b|/(a+b)`.
  - Project precision is **RMS CV** = `√(mean CV_i²)`. It is never the arithmetic mean of CV_i or of HARD (Lawie & Stanley 2012).

**Notes (IMP).**
1. IMP INFO issues are raised **once per (table, field, step)**, never per cell (02 §6). Their fingerprint key is `table:<name>` with `field` = the canonical field and `value` = the step code, e.g. `N04_DIGITS`.
2. IMP-016 is the generic release gate. IMP-011, IMP-012 and IMP-014 carry the evidence for their inference kinds, and COL-006, SUR-005 and SUR-014 report the *geological* consequences. One unconfirmed dip-convention inference therefore produces one IMP-016 issue plus the SUR-005 findings. These are not double-counted, because IMP feeds the Integrity component and SUR feeds the Survey component.
3. IMP-013 "suspended" is recorded in the rule-execution matrix as `NOT_APPLICABLE (suspended by IMP-013)`. Suspended rules are never reported as passed.
4. IMP-018 deliberately has no built-in vendor limits. The research stream could not verify current maximum ID lengths, so each export profile must state its own (Appendix E).

**Notes (COL).**
1. **Wedges, re-drills, twins.** COL-004 classifies collar pairs. COL-021 checks the declared linkage. SUR-025 tests the shared upper trace. CRS-010 removes duplicated parent samples from estimation. CRS-006 compares twins. The SUR-016 proximity test excludes parent–daughter pairs above the kick-off depth (01 §6.8).
2. **EOH division of labour.** COL-007 is raised once per hole and carries the fix proposal with its evidence ranking. SUR-006 and INT-005 are raised per offending row and link to the COL-007 issue in `related_hole_ids`/evidence. Accepting the COL-007 fix resolves all of them on re-run.
3. **COL-011 drape options** differ in meaning. A vertical drape keeps along-hole depths and moves the trace. An along-hole drape keeps the trace and changes every depth. The choice is recorded in the change set's `reason`. A drape is never offered while COL-012 or COL-024 is open for the same campaign: a datum error must be fixed as a datum error.
4. **COL-020 deviation from the research default.** The research proposed WARNING ≥ 10 m and ERROR ≥ 50 m for planned vs as-drilled displacement. Pads are moved deliberately for access, so this catalogue uses INFO ≥ 10 m and WARNING ≥ 50 m. The value of the test is detecting a *wrong record*, which (a), (b) and (e) do.
5. **COL-021 status vocabulary.** 02 `HOLE_STATUS` has `COMPLETED, ABANDONED, IN_PROGRESS, PLANNED, UNKNOWN`. `CANCELLED` and `REDRILLED`, `hole_type` `EXTENSION`, and the fields `kickoff_depth_m`, `replaced_by_hole_id` and `exclude_from_estimation` are requested in Appendix C.
6. **COL-006 vs COL-024 vs VER-002.** A wrong horizontal datum can be seen three ways: between campaigns (COL-006), against the DEM (COL-024) and between database versions (VER-002). All three report the same PROJ candidate, so the reviewer sees one consistent explanation.

**Notes (SUR).**
1. **Station policy** (01 §6.3). Only `is_accepted` stations of the active set (SUR-021) are used. Duplicate depths keep the first by `src_row` for desurvey only, and SUR-002 reports them. The last direction is held to EOH; SUR-008 reports the extrapolated length.
2. **Order of the magnetic rules.** SUR-027 screens stations first. SUR-013 then looks for spikes among the stations that passed. SUR-014 handles depth-constant reference offsets. A station is therefore never reported twice for the same cause.
3. **Unit equivalence for clients migrating Oasis profiles.** deg/30 m = 30 × deg/m. GEOVALID displays both units for SUR-010 and SUR-011.
4. **Candidate B7 (Surpac straight/curved flag) is merged into SUR-015.** The canonical schema has no trace-type field, so the flag is read only as source metadata. Exports write a trace type consistent with the survey data.
5. **SUR-027 defaults.** The ISCWSA 300 nT / 0.25° tolerances are for MWD tools in oil-field practice. Mining multishot tools are noisier, so the base profile uses 500 nT / 0.5°, and the strict values are a profile switch. The magnetite skarn, IOCG and BIF profiles escalate SUR-027(b) to ERROR (§4).

**Notes (ASY).**
1. **Unit evidence precedence** (ASY-001): certificate header > method dictionary > magnitude inference. Each column stores `unit_source`. A unit inferred from magnitude is never final without confirmation (IMP-016).
2. **Project-defined assay rules** use `ASY-901…999` (01 §5.11). Example: `CuAS <= Cu * 1.05`. The built-in partial ≤ total relations are already in ASY-006(c) and need no user rule.
3. **ASY-009 ladder steps 2–3** need `method.technique` / `method.charge_g` and the QAQ-018 disposition link. They extend the 02 §4.9.3 algorithm (Appendix C). Step 3 is the only way a re-assay may replace an original for a whole batch, so ASY-021 can audit it.
4. **ASY-020 is the strongest single verification a CP can cite** (NI 43-101 Item 12): it is the only rule that can see a plausible but wrong number. Its project error rate and audited fraction are printed in the JORC T1.07 and NI-12 assessments (01 §8.3–8.4).
5. **ASY-025 vs QAQ-014.** ASY-025 finds swaps between routine samples from their chemistry. QAQ-014 finds swaps and sequence shifts using QC samples as fixed markers. A pair flagged by both is reported once by QAQ-014, with ASY-025 as supporting evidence.
