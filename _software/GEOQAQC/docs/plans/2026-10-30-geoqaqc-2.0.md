# GEOQAQC 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn GEOQAQC 1.1 (single-file Tkinter QA/QC tool) into a modular 2.0 that cleans raw data automatically, attributes every QC problem to a sample-chain stage with a remedy, and writes a Persian consultant report in HTML, PDF and DOCX.

**Architecture:** The 1.1 analysis code moves, almost unchanged, into a `geoqaqc` package. New layers sit on top of it in sequence: cleaning, then analysis extensions, then diagnosis. Charts are built once as renderer-neutral `Figure` objects and drawn by matplotlib, in a dark theme for the app and a light theme for the report. The report is a neutral document model written out by an HTML writer (with Edge or Chrome turning it into a PDF) and a DOCX writer.

**Tech Stack:** Python 3.9+, Tkinter, matplotlib, python-docx, pytest (dev only), PyInstaller (build), GitHub Actions (windows-latest).

**Spec:** `_software/GEOQAQC/docs/specs/2026-10-30-geoqaqc-2.0-design.md`

## Global Constraints

- Root folder: `_software/GEOQAQC/`; package `geoqaqc/`; entry point stays `GEOQAQC.py`; `APP_VER = "2.0"`.
- Python 3.9 compatible: `from __future__ import annotations`, no `match`, no runtime `X | Y` types.
- Runtime deps are exactly `matplotlib` and `python-docx`; everything else is stdlib. `pytest` is dev-only.
- App UI and chart labels are English; the report is formal Persian with English technical terms; Persian digits are used in Persian prose and tables.
- **A genuine QC failure is never removed.** Cleaning excludes only data errors (C01–C18) and logs every action.
- No threshold may be a literal in `analysis.py`, `cleaning.py` or `diagnosis.py`. Every threshold comes from `S` (settings), `C` (criteria) or `RB` (RuleBook), so it can be edited, saved in the session and written to the protocol.
- With every cleaning rule switched off, 2.0 reproduces the 1.1 numbers on `sample_data/assay.csv`.
- Every commit ends with the session attribution lines.

## Review Focus

1. **Decimal comma and semicolon CSVs.** In `0,123` the comma must be read as a decimal point, not a thousands separator (1.1 strips commas, which turns it into `123`). Thousands such as `1,234.5` must still parse. Test in Task 1.
2. **Persian or Arabic-Indic digits** (`۰٫۱۲۳`, `٠٫٥`) and `٫` / `٬` separators in lab files from Iranian labs must parse as numbers. Test in Task 1.
3. **Excel workbooks.** Users will pick a `.xlsx` file as "raw data". It must load from the first sheet without openpyxl, or fail with a plain message. Test in Task 2.
4. **Non-ASCII output paths** (a Windows profile folder or project name in Persian). The HTML, DOCX and PDF writers and the browser file URI must all work. Test in Task 11.
5. **Sparse datasets** (no certificates, no duplicates, one element, no batch column). Analysis, diagnosis and report must still complete and explain each missing section instead of crashing or leaving it empty. Test in Task 10.

- Rule order inside `clean_values`:
  1. C01 log the dropped rows.
  2. C02 exact duplicate rows → `dropped=True`.
  3. C03 duplicate IDs, following `dup_id_policy`; the re-assays get `dropped=True`.
  4. Re-parse every raw value with `parse_value` (C04–C07).
  5. C08 `>` → `excl[el]`.
  6. C09/C10 certificate matching and unit conversion.
  7. C11 column unit mismatch.
  8. C12 single unit or decimal error.
  9. C13 CRM swap.
  10. C14 CRM that is really a blank.
  11. C15 blank that is really a CRM.
  12. C18 sequence notes.
  - A rule whose `clean_Cxx` switch is off is skipped. When C04–C07 are off, the value keeps the 1.1 `fnum`/`dl_flag` result.
- Rule semantics are exactly as in spec §4. In C13, z is computed against the effective SD (the certificate SD, otherwise the observed SD of that CRM and element). "Fraction" means the share of the sample's elements that have a certificate for both the labelled CRM and the candidate CRM.

### Task 5: New analyses

**Files:**
- Modify: `geoqaqc/analysis.py`
- Create: `tests/test_analysis_new.py`

**Interfaces:**
- Produces new fields on existing records:
  - **CRM record:**
    - `drift = {slope, total, p, sig}`: OLS of bias on rank; `total = slope * (n - 1)`; `sig = p < RB["drift_p"] and abs(total) >= RB["drift_total"]`.
    - `cusum = core.cusum(z, RB["cusum_k"], RB["cusum_h"])`.
    - `batch_bias = [{batch, n, bias, zmax}]`.
    - `rsd_ratio`: observed RSD divided by certified RSD, or `None`.
    - `excluded = [{sample, reason}]`.
  - **Blank record:**
    - `rho`, `rho_p`: Spearman of the blank value against the previous value.
    - `fail_after_high_pct`, `fail_other_pct`: high grade means previous value > `S["carry_kdl"]` × DL.
    - `median_ratio`.
    - `btype`.
  - **Duplicate record:**
    - `maxmin = {limit_hard, ratio_line, fail_pct}`: `limit_hard` is the GOOD cut (index 2) of that class's HARD criterion; `ratio_line = (1 + h/100) / (1 - h/100)`.
